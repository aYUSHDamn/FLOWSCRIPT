# FlowScript & FlowScript Studio

FlowScript is a research-oriented domain-specific language and compiler for sequential, safety-critical workflows. It features a complete compiler pipeline, property-based device sensing, global invariants, local contract assertions, explicit fault recovery blocks, and automated safety-constrained recovery synthesis using bounded Breadth-First Search (BFS).

**FlowScript Studio** is the companion local web IDE providing interactive workflow development, real-time multi-stage compiler inspection (Tokens, AST, IR bytecode, Optimized IR), and synthesis telemetry visualization.

---

## 1. Prerequisites

- **Python**: Python 3.12 or higher.
- **Dependencies**: None. FlowScript and FlowScript Studio are built entirely with the **Python standard library** and vanilla web technologies. Zero external packages, zero npm installs, and zero API keys are required.
- **Supported Browsers**: Any modern browser (Chrome, Edge, Firefox, Safari). Works 100% offline without external CDNs.

---

## 2. Quickstart: Launching FlowScript Studio

From Windows PowerShell (or command prompt) in the project root directory:

```powershell
python server.py --port 8000
```

To bind to a specific network interface or port:

```powershell
python server.py --host 127.0.0.1 --port 8080
```

### Local Playground URL

Open your browser to:

```
http://127.0.0.1:8000/
```

The web interface connects directly to the local Python compiler backend over REST API endpoints (`/api/compile`, `/api/run`, `/api/examples`, `/api/health`).

---

## 3. Command-Line Compiler Interface (CLI)

You can also run the FlowScript compiler directly from the terminal without the web server:

```powershell
# Compile and execute a workflow
python main.py examples/temperature.flow

# Execute with compiler optimizations disabled
python main.py examples/temperature.flow --no-opt

# Inspect compiler intermediate representations
python main.py examples/temperature.flow --tokens
python main.py examples/temperature.flow --ast
python main.py examples/temperature.flow --ir

# Output recovery synthesis telemetry in CSV format
python main.py examples/synthesis_demo.flow --telemetry
```

## 5. Using FlowScript Studio

### Compiling and Running
1. **Choose an Example**: Use the top-left dropdown or sidebar list to load a workflow.
2. **Edit Code**: Type directly in the central editor. Features include line numbers, FlowScript syntax highlighting, auto-indentation, and dirty-state tracking.
3. **Run Workflow (`Ctrl+Enter` or Run button)**: Compiles the source and runs it on the simulated virtual machine. Live output, device actuation events, and final device states appear in the **Console** tab.
4. **Compile Only (`Ctrl+B` or Compile button)**: Runs lexing, parsing, semantic analysis, recovery synthesis, and IR optimization without executing the VM.

### Multi-Stage Compiler Inspector Tabs
- **Console**: Live execution feed, device transition badges (`fan → ON`), device state HUD, and runtime variables.
- **Diagnostics**: Plain-English error explanations with jump-to-line links and actionable fix suggestions.
- **Tokens**: Filterable lexical token stream showing token type, value, and source line.
- **AST**: Structural syntax tree representation.
- **IR**: Raw stack-machine instructions generated by the IR generator.
- **Optimized IR**: Instructions after dead-code elimination and constant folding, showing instruction count reduction percentages.
- **Recovery Synthesis**: Visualizes search depth, states explored, invariant rejections, and the synthesized step-by-step action plan timeline.

### Guided Interactive Tour
Click the **Tour** button in the top navigation bar to launch the 6-step guided walkthrough:
1. Basic Workflows & Syntax
2. Device Sensing & Conditions
3. Compiler Optimization (Constant Folding & DCE)
4. Safety Contracts (`INVARIANT`, `REQUIRE`, `ENSURE`)
5. Explicit Fault Recovery (`TRY ... RECOVER`)
6. Automated Recovery Synthesis & Research Telemetry

## 7. Known Limitations & Research Context

1. **Discrete Simulation Abstraction**: Simulated devices operate in discrete `ON` and `OFF` states with instantaneous simulated effects. Physical deployment on real hardware requires modeling continuous dynamics, actuator slew rates, and network latency.
2. **Memoryless Invariants**: Global invariants are pure state predicates evaluated on the immediate post-transition state without temporal history dependencies (e.g. LTL).
3. **Serial Actuation**: The current IR stack machine and synthesis engine emit serialized device actions; concurrent multi-device actuation is not currently modeled in the bytecode.
